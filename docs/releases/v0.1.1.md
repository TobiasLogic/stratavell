# Stratavell v0.1.1

A patch release that makes lexical search much faster. There are no API, database schema or configuration changes, and it is still pure Go with no new dependencies.

## Search latency

Measured with `TestSearchLatencyProfile`: a generated 1,200-turn coding session, 200 searches over eight queries, one 8-core laptop CPU. v0.1.0 and v0.1.1 ran on the same machine in the same session.

| measurement | v0.1.0 | v0.1.1 |
|---|---|---|
| p95, 13,200 indexed chunks | 35.8 ms | **6.5 ms** (81.8% lower) |
| p95, 3,400 indexed chunks | 10.6 ms | 3.1 ms |
| p95, 13,200 chunks, freshly reopened database (new engine and connections) | 76.5 ms | 14.6 ms |

v0.1.0's documentation reported 33.7 ms at 13.2k chunks from an earlier run.

These numbers cover one generated workload and eight queries. They are not a broad search benchmark.

## What was wrong

Profiling showed the slow queries were not limited by SQLite's speed:

- **Common words were added back.** Term pruning refilled every query to three words with the rarest remaining ones, even when those appeared in 40 to 75% of all chunks. Full-text search then scored a large part of the corpus.
- **Two-letter words looked rare.** Document frequency ignored them, so `go`, present in 74% of chunks, was counted as 0%.
- **The stale-file check ran per candidate.** It made one or two queries for each search candidate and counted every later write. It is now one `EXISTS` query per search.
- **Path queries also ran full-text search.** A query that is a single file path now uses the exact path index only, when that index has hits.

`stratavell vacuum` also merges FTS5 index segments now.

Alternatives tested and not adopted:
- a native C SQLite build: 1.85x faster on the same SQL, but it needs cgo
- `mmap_size`: no effect
- an in-memory index prototype: fast, but no longer needed

The measurements are in `docs/experiments.md`.

## Behavior change: common-term fallback

When a query's rare words matched nothing, v0.1.0 still searched its common words: `value_42 compute` returned chunks that merely contained "value" or "compute". Since v0.1.1, words in more than 20% of chunks are dropped whenever a rarer word is present, so such a query returns no full-text hits.

A query made only of common words still searches its one or two rarest words. Exact path, symbol and id lookups are unaffected.

## Unchanged results

- **Benchmark output:** all 26 deterministic regression runs are identical to the published results in every deterministic field: seed 1 of the 64k main, component-matched and ablation suites. That includes recoverability per fact kind, injected evidence, tokens and simulated costs.
- **Golden smoke run:** `TestDeterministicSmoke` is unchanged.
- **Regression tests:** the new tests fail on v0.1.0 and pass on v0.1.1.

## Install

```bash
go install github.com/TobiasLogic/stratavell/cmd/stratavell@v0.1.1
```

Or download an archive below and verify it with `SHA256SUMS`.

What comes next: internal optimization is frozen after this release. The next priorities are independent benchmarking and agent integrations (see `docs/roadmap.md`).
